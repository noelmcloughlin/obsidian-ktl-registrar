# References

* [LOKF specification](lokf-specification.md)
* [LOKF Toolkit](lokf-toolkit.md) - The `lokf` PyPI package that the `.lokf/` sidecar depends on (`lokf[build]>=0.8.0`) and runs through the justfile recipes and the website's sync; a separate resource from the LOKF specification website.
* [OKF Specification (v0.2)](okf-specification.md) - The Open Knowledge Format v0.2 specification: a folder of Markdown files with YAML frontmatter, one concept per file, with a type as the only required field, plus the provenance, trust and lifecycle fields and attested computations.
* [Obsidian Plugin Guidelines](obsidian-plugin-guidelines.md) - Obsidian's developer guidelines for community plugins, for example sentence case in UI text, setHeading in a settings tab, no innerHTML, no detaching leaves in onunload and no hardcoded styling, which eslint-plugin-obsidianmd enforces in this repository.
* [Commands and Settings](commands-and-settings.md) - Every KTL Registrar command with its id and name, what the status-bar item does when clicked, and the settings groups under Settings → KTL Registrar, including Known LOKF types for a domain schema, from docs/using.md and src/main.ts.
