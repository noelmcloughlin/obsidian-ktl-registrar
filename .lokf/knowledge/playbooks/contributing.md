# Overview

`CONTRIBUTING.md` was rewritten on 2026-09-14 from a design log back into a
checklist: each rule is now a line or two linking to where its reasoning
lives (a code comment, a workflow header, a `docs/` page) rather than
restating it, and `npm run check` - the new combined `build && lint &&
smoke-test` script, the same three steps [build.yml](../../../.github/workflows/build.yml)
runs - holds the file itself to a 1000-word budget via a drift-guard section
`scripts/smoke-test.ts` gained the same day. That guard also checks two other
facts the prose can't check itself: that the class vocabulary
`docs/for-the-curious.md` documents matches the pinned `lokf-vocab.json`
manifest, and that the import-free module list below names exactly what the
suite imports - the previous version of this file had drifted to naming
`validator.ts` alone after the suite grew to ten modules, caught and fixed
earlier the same day.

`src/` splits in two. The pure modules take already-parsed frontmatter and
pull in nothing at run time - not Obsidian, not a YAML library - so
`npm run smoke-test` runs them under plain Node with no Obsidian install:
`validator`, `locator`, `vocab`, `graph`, `fixes`, `propose`,
`report-filter`, `suggest-context`, `affordances`, `fields`. Everything else
(`main.ts`, the report view, the settings tab, the modals) needs a real
Obsidian `App`, has no automated test, and is checked by hand in a vault -
which is why logic worth testing moves *out* of `main.ts` rather than being
tested through it (the saved-settings merge rule lives in `vocab.ts` as
`mergeSavedSettings` for exactly this reason).

`main.js` is generated and git-ignored, so a fresh clone/checkout has none at
all and Obsidian reports a bare "Failed to load plugin" until
`npm install && npm run dev` (or `npm run build` for a one-off) has run.

Since 2026-09-14, `eslint.config.mts` promotes four `obsidianmd` settings-tab
and `createEl` rules from warning to error (the recommended config only
warns, and `eslint .` used to pass regardless); lint findings are still
treated as upstream review feedback, fixed in the code rather than by
widening `eslint.config.mts`'s two deliberate vocabulary exceptions. CI's
`lint-and-docs.yaml` gained a matching hardening the same day - see
[Quality gates](quality-gates.md). `src/lokf-vocab.json` is generated by
`npm run build-vocab` from the pinned LOKF schema and kept identical to LOKF
Curator's own copy; refresh and commit it only when that schema bumps.
`validator.ts` itself is unchanged: import-free, and checking only *shape* -
the OKF base layer (`okf/*`, behind `checkOkfBaseLayer`) and the LOKF
semantic layer (`lokf/*`) - never a §5 field's credibility or runtime
attestation.

The releasing walkthrough (signing, the `release` Environment, repository
settings) moved out of this file entirely on 2026-09-14 to
[lokf-agent-skills' docs/releasing.md](https://github.com/noelmcloughlin/lokf-agent-skills/blob/main/docs/releasing.md)
and `docs/signing-commits.md`, both confirmed present; this bundle's own
[Releasing](releasing.md) concept still describes the pipeline directly from
`semantic-release.yml`/`release.yml`, which did not change.
